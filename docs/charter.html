Project Charter

Reliable Probabilistic Time Series Imputation

Authors: Vladislav Voronin, Kirill Lalayants, Mikhail Bezrukov, Fedor Zhirkov
Supervisor: Vitaliy Pozdnyakov
Program: Artificial Intelligence and Financial Technologies. Course: Models of Sequential Data, 2026.

1. Research question and claim/hypothesis

Shared research problem: Plausible reconstructions and low median error can hide unreliable uncertainty. Narrow data, leakage and unsuitable metrics can distort evaluation (Bergmeir, 2023).

Research question: When are native predictive distributions reliable, and how does two-sided forecasting adaptation affect calibration?

Hypotheses: (1) Contiguous blocks are harder than scattered points. (2) Median accuracy and calibration can disagree. (3) Blending left and right forecasts can change calibration in either direction. We report observed differences on this setup, without claiming statistical significance.

2. Task, horizon, and intended output

Task: Probabilistic retrospective imputation. Inside each window we hide 24 or 128 values, either as scattered points or as contiguous gaps. Each pair (scattered vs contiguous) has the same hidden count, and both window edges stay observed.

Intended output: Predictive quantiles for each hidden value; the median gives the point estimate. Tables by model, dataset, mask type and hidden count; reliability curves; coverage and width plotted along the gap position; code, poster and report.

3. Data source, access, licensing, limitations

Datasets: ETT_h1, Electricity and BeijingAir. These are standard imputation benchmarks used in TSI-Bench (Du et al., 2024).

Access: Load the public benchmark versions and keep a local copy. Publish loading code, not the raw data. Original dataset licenses apply.

Limitations: Masks are synthetic. Only eligible complete windows are used. Channels are dependent, so cases are not independent repeats. Overlap with Chronos pretraining data cannot be ruled out.

EDA: One small notebook with data coverage, missing-value summary, scale differences and typical seasonal patterns per dataset.

4. Train-validation-test protocol and leakage audit

Split: Chronological 60% / 20% / 20% train / validation / test for each dataset.

Protocol: Scaling, Kalman parameters and CSDI are fitted on train only. Settings are frozen after validation. Chronos-2-small is used frozen, without fine-tuning.

Leakage audit: Only hidden targets are scored. True values inside the mask are never given to any model. Each full window stays inside its split. All methods use the same saved masks; validation and test use different random seeds.

6. Baseline ladder

Classical: Gaussian Kalman smoother — a classical probabilistic state-space baseline. It conditions on all observed positions; process and observation variances are fitted on train. Uncertainty is the conditional Gaussian distribution of each missing measurement (including observation variance), not only of the latent state.

Deep baseline: CSDI via PyPOTS (Tashiro et al., 2021) — a trained conditional diffusion imputer. Pooled univariate training on a mixture of point and block masks, using the same masked windows. Uncertainty comes from sampled missing trajectories; we keep 100 draws per window if feasible. The point estimate is the empirical sample median.

Foundation model: Chronos-2-small — a frozen quantile foundation forecaster. It forecasts from the left context and from the reversed right context; other hidden runs stay masked. Native forecast quantiles are used; the two-sided blend is our adaptation.

Literature basis: Bergmeir (2023) on evaluation pitfalls; TSI-Bench (Du et al., 2024) for datasets and point/block comparison; Adler et al. (2026) for calibration diagnostics; Tashiro et al. (2021) for CSDI; Gneiting & Raftery (2007) for proper scoring rules; PyPOTS and Chronos documentation.

7. Method and the smallest decisive experiment

Method: For Chronos, forecast the gap from the left context, forecast it from the reversed right context, then blend matching quantiles position by position. This is a heuristic, not exact conditional inference.

Analytical motivation: For a Gaussian random walk with noiseless endpoints and a 24-step gap, blended quantiles near the midpoint are about 1.4 times wider than the exact Gaussian bridge. This is an analytical illustration, not a measured result, and it shows why blending can miscalibrate.

Matched comparison: All three methods are scored on identical masks and targets: 24 or 128 hidden values, scattered or contiguous, with the same hidden count inside each pair.

Decisive ablation: Left-only vs right-only vs blended Chronos quantiles on identical targets, with coverage and width plotted along the gap position.

8. Planned ablations and robustness checks

Mask type and size: scattered vs contiguous at 24 and 128 hidden values.

Chronos direction: left-only, right-only and blended quantiles.

CSDI sampling check: quantile stability with 50 vs 100 draws.

Kalman check: include observation variance and inspect seasonal misspecification.

No fine-tuning of Chronos, no extra datasets or missingness mechanisms, and no hyperparameter search beyond validation of the fixed settings.

9. Compute budget, runtime, and fallback

Chronos: smoke test on Apple MPS, with CPU/CUDA fallback.

CSDI: required for the comparison. An early feasibility check, then at most six GPU-hours in total. Save checkpoints and keep the best validation checkpoint. This is a budget cap, not a runtime guarantee.

Fallback: if compute is not enough, reduce the shared scope (for example, fewer evaluated windows) rather than dropping a method. Do not add a replacement architecture.

10. Roles, repository, and weekly plan

Team roles: One main owner each for data and masks/evaluation, the Kalman baseline, CSDI, and Chronos adapters. Everyone contributes to the report.

Repository: A small GitHub repo with Python scripts, one config, pinned dependencies and README commands for data preparation, training/inference and evaluation. Save masks, predictions and metrics so tables and plots can be rebuilt without rerunning models. Record individual contributions in README.

11. Main scientific and execution risks

Claim boundaries: CSDI — finite draws introduce quantile error, and compute must pass the pilot. Kalman — Gaussian assumptions may fail; fitted-parameter uncertainty is excluded. Chronos — forecast calibration does not imply imputation calibration.

Scientific limits: synthetic masks; eligible complete windows only; dependent channels; possible pretraining overlap; finite diffusion samples; Gaussian misspecification. Results describe this setup and this blending rule, not all foundation models.

Execution risk: CSDI is needed for the full comparison. If no usable checkpoint is obtained within budget, report the experiment as incomplete and the CSDI part as untested.

12. Intended AI use and how outputs will be checked

LLM help for literature notes, text editing and routine code. Final numbers come only from saved experiment outputs. We check formulas and model usage against the cited papers or official code, and rerun evaluation to reproduce the tables and figures.
